# Release Notes

## 输入

- 版本号与发布日期
- 上一次发布以来的提交 / PR 列表
- 已知问题与升级注意事项

## 结构

```md
# v1.4.0 (2026-11-09)

## 亮点
一句话说明这个版本最重要的用户价值。

## 新功能
- **功能名** — 用户能做什么，入口在哪里。

## 改进
- ...

## 修复
- ...

## 升级说明
- 是否需要迁移、配置变更、兼容性影响。

## 已知问题
- ...
```

## 写作规则

- 面向用户描述"能力变化"，不要照抄提交信息。
- 每条更新都能让读者判断"是否影响我"。
- 破坏性变更必须放在最前面，并给出迁移步骤。
- 没有内容的分类直接删除，不保留空标题。
- 链接到 issue/PR 时使用完整编号。
